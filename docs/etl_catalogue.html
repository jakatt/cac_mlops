★ Corriger plutôt qu'arrêter — principe et bilan réel
Chaque anomalie est traitée au niveau le plus bas possible · toute correction est journalisée (AUTO_CORRECTED dans le rapport de validation, event=auto_corrected dans les logs Prefect / Loki)
1. AUTO_CORRECTED anomalie connue → corrigée, tracée, aucune alerte › 2. AUTO_RETRY incident transitoire → nouvel essai › 3. WARNING anomalie inconnue mais sans risque → email, le pipeline continue › 4. CRITICAL donnée inexploitable → arrêt, @Production inchangé

1 Découverte & téléchargement — download_task

Résolution & téléchargement 7
Sous-étapeCe qui se passe
Résolution dynamique des URLs AUTO_CORRECTEDAPI data.gouv.fr interrogée à chaque run — aucun nom de fichier ni URL codé en dur : un renommage côté ONISR est absorbé sans intervention
Filtrage des ressourcesFormat CSV uniquement, taille ≥ 500 Ko, exclusion des titres "enrichi/consolidé/traitement/qualité/bilan/synthèse/analyse/open data/résumé" (datasets dérivés à écarter)

Seul un fichier réellement inexploitable (séparateur inconnu, colonne obligatoire absente, taille < 500 Ko = page d'erreur) est supprimé et stoppe le flow
Réseau instable AUTO_RETRY / CRITICALLa tâche download-raw-data est rejouée automatiquement (2 réessais, 30 s d'intervalle — Prefect). Arrêt seulement si data.gouv.fr reste injoignable
IdempotenceFichiers déjà présents pour l'année → téléchargement sauté (un réessai ne re-télécharge que ce qui manque)
2 Validation Pandera — validate_task
src/data/schema_validator.py · known_fixes.py — load_and_validate_year() · 3 niveaux, sur les vraies données
Level 1 — Format 3
CheckCe qui se passe
Fichier au nom inattendu AUTO_CORRECTEDMatching strict par mot-clé, puis fallback par similarité (difflib, seuil 0,75) : le fichier est retrouvé et utilisé, correction journalisée (event=auto_corrected check=filename_fuzzy_match) — plus d'alerte email
Séparateur / encodage AUTO_CORRECTEDLecture tentée avec ; / , / tabulation × utf-8 / latin-1 / utf-8-sig — la première combinaison qui donne plusieurs colonnes est retenue
Fichier introuvable, vide ou illisible CRITICALAucun fichier ne correspond à une catégorie, fichier de taille 0, ou aucune combinaison séparateur × encodage exploitable → arrêt
Level 2 — Schéma 8
CheckCe qui se passe
Noms de colonnes AUTO_CORRECTEDnormalize_column_names() — BOM UTF-8 en tête (\ufeffNum_Acc), guillemets, espaces parasites, casse différente (NUM_ACC, Jour) → ramenés au nom attendu
Renommages connus AUTO_CORRECTEDapply_known_fixes() — Accident_Id → Num_Acc (ONISR 2022, appliqué en production) et espaces insécables / superflus sur les colonnes texte
Lignes dupliquées AUTO_CORRECTEDLignes strictement identiques supprimées — cas réel : 2 doublons dans lieux 2024
Types de colonnes AUTO_CORRECTEDPandera coerce=True — colonne lue avec le mauvais type reconvertie (appliqué chaque année sur les 4 tables)
Valeurs hors nomenclature AUTO_CORRECTEDCode inconnu (lum=9) ou texte parasite (vma="N/C") dans une colonne codifiée → ramené à -1 = « non renseigné » ONISR (NaN pour les colonnes décimales), puis 2ᵉ validation ; si elle échoue encore → WARNING, le pipeline continue. Auparavant, une seule valeur de ce type laissait toute la table non typée
Colonnes ONISR connues non utilisées INFOadr, an, v1, v2, occutc… — présentes chaque année, ignorées par le modèle : simple information (étaient un WARNING à chaque ETL)
Colonne réellement nouvelle WARNINGColonne absente du schéma et de la liste des colonnes connues → signalée (ONISR a peut-être enrichi son format), ignorée, le pipeline continue
Colonne obligatoire absente CRITICALAprès toutes les corrections ci-dessus, une colonne requise manque toujours → arrêt
Level 3 — Qualité 4
CheckCe qui se passe
Volumétrie WARNINGNombre d'accidents hors de [40 000 ; 90 000] — données potentiellement tronquées
Taux de NaN WARNING> 30 % sur une colonne utilisée par le modèle (les colonnes ignorées ne sont plus contrôlées : elles levaient 3 WARNING inutiles par an)
Coordonnées hors métropole INFO / WARNING~5-6 % des accidents chaque année sont en DROM/COM, légitimement hors du cadre métropole → INFO ; WARNING seulement au-delà de 10 % (coordonnées probablement corrompues)
Valeurs grav WARNINGTable usagers — valeurs hors {-1,1,2,3,4} restantes après correction

Niveau global du rapport = le pire niveau rencontré (CRITICAL > WARNING > OK). CRITICAL lève une exception et stoppe le flow ; WARNING envoie une alerte et laisse le pipeline continuer ; AUTO_CORRECTED et INFO sont informatifs (traités comme OK, sans email).
